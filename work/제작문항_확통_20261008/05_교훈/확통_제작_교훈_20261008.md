## 1. 설계 교훈 (후보 규칙 PS-01 ~ PS-10)

각 항목: **적용 조건 → 검사 → 실패 시 조치**.

### PS-01 핵심 번역은 보존하고, 조건의 역할·필수 판단·질문 중 둘 이상을 바꾼다
- 적용: 기출의 "핵심 풀이 방식을 차용"하는 변형 제작(KG-A35 숫자변형 금지의 실천법).
- 검사: 문항마다 `설계.핵심판단`(2~4개)과 `설계.원문과의차이` 를 적고, 원문과 같은 판단만 남는 문항은 폐기. 이번 배치의 네 원문은 난도 원천이 달랐다 — 6월28 번역(홀짝 벡터), 9월28 가중치 보존·되돌아오기 홀짝, 9월30 **번역 한 번뿐(중간 난도)**, 수능28 경계 처리. 원천이 하나뿐인 원문(9월30)은 번역 뒤에 **역방향·조건부·비복원·분포 결정·혼합·부등식** 중 하나를 반드시 결합해야 4점 난도가 된다.
- 실패 시: 블라인드 검토 난도가 '중' 이하이면 결합 축을 하나 더 넣는다(C10: 교차 조건 추가, B07: 혼합으로 교체).

### PS-02 세트 내 중복은 설계 단계에서 서명으로 거른다
- 적용: 같은 원문에서 여러 문항을 만들 때.
- 검사: 설계표에 **서명 = (설정, 규칙, 초기 상태, 분모 사건, 분자 사건/질문)** 을 적고 같은 서명이 둘이면 하나를 바꾼다. 조건 상자형은 (가)(나) 가 같은 쌍을 금지. 자동 검사: `build_manuscripts.py` 가 (가)(나) 동일·문면 유사도 ≥0.9 를 경고한다.
- 사례: A02(초기 {1,6}, 4회)=A08(초기 {1,6}, 3회) → A08 을 "모두 앞면" 시작으로. C01(배수·양끝 엄격)≈C02(합·±1 이동) → C02 를 치역 크기로. C06·C08 (가)(나) 동일 → C06 (가)를 합으로. B07(Σ(k−5)²P)⊂B10(Σ(k−a)²P<9) → B07 을 혼합 모집단으로.
- 잔여: C 세트에 "f(1)f(6) 이 6의 약수/배수" 모티프가 C01·C03·C08(+C10 접점) 네 번 — 검토자가 지적. 다음 배치에서는 (가) 유형(곱·합·차·함수관계·치역)을 표로 배분하고 시작한다.

### PS-03 Σ 의 하한은 "항이 0이 되는가"로 정한다
- 적용: Σ f(k) P(X̄=k/n) 꼴 문항.
- 검사: f(0)=0 이면 k=1 부터(원문 관례), 아니면 k=0 부터. 상한은 S 의 최댓값. 범위가 분포 값 범위와 다르면 검토자가 결함으로 잡는다.
- 사례: B07(구)·B10 의 (k−a)² 은 k=0 항이 a²P(S=0)≠0 → 하한 0. B06 은 S≥3 이라 하한 3 으로 써서 범위를 드러냄.

### PS-04 은닉 모집단은 "문면에 적힌 값이 모두 존재 가능한가"까지 검사한다
- 적용: 모집단 구성을 숨기고 적률만 주는 문항(B09).
- 검사: 주어진 적률 (m, σ²) 에 대해 (1) 지지집합 위에서 실현 가능한가(분산 상한: 지지집합 {a..b}, 평균 m 에서 최대 (m−a)(b−m)), (2) **문면이 "0,1,2,3 중 하나"처럼 모든 값을 언급하면 그 값들이 모두 양의 확률을 가질 수 있는가**(1,2 가 존재하면서 같은 적률이 되는 분포가 있는지 선형 탐색). 검산 스크립트에 실현 분포 하나를 `assert` 로 남긴다.
- 사례: σ²=3 은 불가능(최대 2) → σ²=2 로 고침 → 그러나 σ²=2 는 X∈{0,3} 을 강제해 문면과 충돌(검토 지적) → σ²=1 (공 5·3·3·1 로 실현). **같은 문항을 두 번 고쳤다** — 처음부터 (2)까지 검사했어야 한다.

### PS-05 조건은 답의 상당 부분을 바꿔야 한다 (허수 조건 금지, KG-A04 의 정량화)
- 적용: 모든 조건.
- 검사: 조건 삭제 증인(KG-V01)의 개수 변화를 본다. **삭제해도 답이 같으면 삭제**(B08 "m>0" — 다른 근이 n=25/49 로 저절로 걸러짐). 삭제 시 변화가 전체의 수 % 이하이면 "허수 조건"으로 보고 조건을 강화한다(C09 구 (나)의 `≤2f(7)` 은 함수 1개만 걸러냄 → 왼쪽 계수도 2배로 바꿔 두 쌍에서 절단이 답을 바꾸게 함).
- 자동화: 검산 스크립트가 `witness_*` 값이 정답과 같으면 경고한다.

### PS-06 시행 문항의 사건은 관찰값 또는 상태 비교로 서술한다 (중의성 차단)
- 적용: 눈의 수에 따라 조작이 수행되는 시행에서 "배열이 바뀌었다/움직였다" 류 사건.
- 검사: 사건을 (a) 눈의 수로("눈의 수가 3 이하") 또는 (b) 상태 비교로("시행 후의 배열이 그 시행 직전의 배열과 다르다")만 쓴다. "조작이 수행됨"과 "상태가 변함"이 다른 문항(같은 문자 교환은 상태 불변)에서는 (b) 로 확정하고, 다른 해석의 답을 `설계.오개념` 에 기록한다.
- 사례: A03 "4번의 시행 모두에서 카드의 배열이 바뀌었을" → 검토자가 329/323 두 답을 냄 → "시행 직전의 배열과 다를"로 확정(323). A06 "1번째, 2번째, 3번째 시행 후에는 모두 처음과 다르게" → "1번째 시행 후, 2번째 시행 후, 3번째 시행 후에 각각 … 처음과 다르게".
- → 용어교훈 후보 TERM-cand-01 (§4).

### PS-07 오개념 답이 정답과 같으면 그 함정은 없는 것이다 (NL-10 일반화)
- 적용: `설계.오개념` 에 적은 모든 오개념.
- 검사: 검산 스크립트가 `misconception_*` 값이 정답과 같으면 경고. 같으면 (a) 문항을 비대칭으로 바꾸거나 (b) 설계 기록에 "이 오개념은 변별되지 않음"을 명시한다.
- 사례: C03 (나) `7−f(1) ≤ … ≤ 7−f(6)` 의 양끝 역할 교환 오개념은 (가)가 대칭이라 답이 같음(152). 대칭 (가) 로는 방향 오개념을 변별할 수 없음을 기록하고 유지(비대칭으로 바꾸면 다른 조건이 허수가 됨 — 설계 탐색에서 확인).

### PS-08 계산량 상한은 원문과 같은 분류로 셀 수 있는가로 판정한다
- 적용: 상태 전이 문항의 분모(4회 복귀 742, 316 등).
- 검사: 해설이 원문 풀이의 분류(유효 이동 0·2·4, 위치별 가중)를 그대로 써서 끝나는지 확인. 새 분류가 필요하면 시행 횟수나 상태 수를 줄인다. 블라인드 검토자의 풀이 시간을 기록하고 12분 이상이면 재검토 대상.
- 사례: A05(분모 316)·A06(분모 742) — 검토자 "수능 범위를 넘는 계산량". 원문 분모가 742 이므로 원문 분류로 가능하다고 보고 유지하되 **실측 전 보류**로 표시.

### PS-09 난도는 블라인드 검토 뒤에 적는다
- 적용: `설계.난도`.
- 검사: 제작자 목표 난도와 검토자 난도·시간을 나란히 기록. 이번 배치: 제작자 "상~최고난도 목표" 30건 중 검토자 '상' 이상은 A02·A05·A06·A08·C05(5건), 나머지는 '중' 안팎. **번역형(B)과 중복조합형(C)은 구조가 보이면 중 난도**로 떨어진다. 최고난도 세트를 원하면 관점 전환(B07 혼합·B09 은닉·C02 분배)과 교차 조건(C10)을 기본으로 깐다.

### PS-10 조건 상자·문면 관례
- 한 조건에 한 명제(C05 (나)에 부등식·절댓값 4개를 몰아넣었던 것을 (나)(다)로 분리).
- `f(1)+1 ≤ f(2)` 보다 `f(1) < f(2)` (평가원 표기); 이동이 의도면 조건 역할에 적는다.
- 같은 숫자 공이 여러 개면 "숫자 1이 적혀 있는 공 2개, …"(B05). "각각 하나씩 적혀 있는"은 숫자가 서로 다를 때만.
- 객관식 선지는 오름차순, 오답 4개는 각각 특정 오개념의 답(KG-A37). 검사기가 오름차순을 확인한다.
- 단답 확률은 p+q(서로소, 1~999) — 검사기가 검산 JSON 의 pq 와 대조한다.

## 2. 검산·검토 공정 교훈 (PS-11 ~ PS-15)

### PS-11 블라인드 검토 프로토콜(KG-V06 의 실행 절차)
1. `원고_*.json` 에서 **문면·조건상자·선지만** 추출해 `07_검토/블라인드_문면_*.md` 를 만든다(정답·해설·검산 파일 접근 금지를 지시문에 명시).
2. 검토자는 주제별로 분리, 각자 새 디렉터리에서 **독립 전수 열거**(itertools/Fraction) 를 작성·실행. 손풀이와 전수 결과를 둘 다 보고.
3. 보고 형식: `ID: 답, 전수검산, 결함(중의성·허수 조건·선지 누락·문체), 난도·시간, 핵심 한 줄` + 세트 총평(중복·난도 분포·모티프 편중).
4. 수정 문항만 모아 **2차 블라인드**(수정으로 새 결함이 들어오는지).
5. `07_검토/검토기록.md` 에 지적 → 조치 → 결과를 표로 남긴다. 정답 일치만으로 통과시키지 않는다.

### PS-12 형식 검사기는 발문 끝·선지·설계 키를 기계로 본다
- `build_manuscripts.py`: 피할 발문(KG-A13)·'정확히'(KG-A06)·객관식 `은/는?`·단답 `구하시오.` + `(단, …)` 허용·`[4점]`·선지 5개 상이·오름차순·오답 근거 4·단답 1~999·`$` 짝·산문 유니코드 기호·해설 금지 기호(KG-S)·설계 7키·검산 대조·중복 서명. **원고를 코드(dict)로 쓰면 검사·JSON·Markdown·PDF 가 한 소스에서 나온다.**

### PS-13 역방향 문항은 전 범위 유일성을 표로 남긴다
- 값에서 매개변수를 구하는 문항(B01 x, B03 n, B04 n)은 의도한 근만 확인하지 말고 자연수 전 범위(또는 충분히 넓은 범위)를 표로 스캔해 `검산결과.json` 에 남긴다. 검토자는 B04 를 n≤40 까지 다시 스캔했다.

### PS-14 답의 형식은 탐색으로 고른다
- 단답은 자연수가 되는 (표본 크기, 상한, 배율) 조합을 엔진으로 스캔(`설계_탐색_*.py`)해 고른다. 확률은 p+q 가 999 이하가 되는 설계를 택한다(A 세트 분모 ≤ 742).
- 오개념 답이 **그럴듯한 자연수**이면(B04 분산만 쓰면 n=144, B05 복원 공식 192) 함정 가치가 있으므로 설계 기록에 적는다.

### PS-15 엔진은 재사용 자산으로 남긴다
- `04_검산/engines.py`: `run_chain(init, step, trials, cond, event, weights)`(상태 전이·조건부·비균등 눈), `flip_step`, `swap_step`, `dist_sum`/`dist_sum_norep`(복원·비복원 합 분포), `count_functions`, `H`. 다음 확통 배치는 이 파일을 복사해 시작한다. 설계 탐색은 `설계_탐색_*.py` 처럼 후보를 한 번에 표로 찍는다.

## 3. 환경·출력 교훈 (PS-16 ~ PS-17)

### PS-16 원문은 DB 에서 읽고, 문체 상수는 원문 문장에서 뽑는다
- `items.raw_text` 를 읽어 "숫자 $0$, $1$, $2$가 각각 하나씩 적혀 있는 세 개의 공이 들어 있는 주머니 … 다시 넣는 시행" 같은 문장을 상수(`BAG3`, `CARD6`, `JUNE_RULE`, `SEP_RULE`, `X6`)로 두고 재사용하면 문체 편차가 줄고 검토자의 문체 지적이 거의 없었다.

### PS-17 클라우드 PDF: 한글 글꼴과 KaTeX contrib 를 먼저 확보한다
- 컨테이너에 한글 글꼴이 없다(IPA·WenQuanYi 만). `cdn.jsdelivr.net/gh/notofonts/noto-cjk@main/Sans/OTF/Korean/NotoSansCJKkr-{Regular,Bold}.otf` → `~/.fonts` + `fc-cache`. (GitHub raw·Google Fonts zip 은 프록시에서 403/HTML.)
- `ngd2-figtool/회귀자료/.../vendor/katex` 에는 `contrib/auto-render.min.js` 가 없다 → jsDelivr 에서 받아 `06_출력/vendor/katex/contrib/` 에 둠. 없으면 `renderMathInElement` 미정의로 `window.__rendered` 대기가 타임아웃된다.
- Playwright 는 `executable_path='/opt/pw-browsers/chromium-1194/chrome-linux/chrome'`. 검사: `.katex-error` 0, `.katex` 노드 수, `pdftoppm` 으로 한 쪽을 그려 글꼴·수식을 눈으로 확인.
- `markdown` 패키지가 없으므로 JSON→HTML 을 직접 만든다(`06_출력/build_pdf.py`). 원고를 dict 로 둔 덕분에 markdown 변환이 필요 없었다.

## 5. 다음 배치에서 바로 쓸 체크리스트
